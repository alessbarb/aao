## Bounded implementation decision for RA-01 (NT-01-1 through NT-01-5)

RA-01 implementation was not attempted in this change. The policy's §3.4.1 identifies the normative list as the §3.4.3 table, but the table is not an implementable, unambiguous route registry as currently written:

- Some entries are conceptual rather than concrete path patterns (for example, “the integrator”, “supervisor code”, “notifier code”, and “content of the trust registry”).
- §3.4.3 explicitly marks several route additions as PM proposals effective only if P5 approves them; the document is itself a draft and says it is not in force until P5.
- The existing operational `policy.json` has an older `protected_paths` string-list schema; `scripts/make_trust_root_files.py` copies it into `registry.json` as R2 classes. There is no separately encoded normative list or path-class mapping in either file. Thus the two material copies can be compared to each other, but the normative third copy and the applicable P5 route decisions cannot be derived safely from current artifacts.

Choosing concrete paths, resolving whether conditional P5 proposals are included, and assigning a route-class representation would amount to selecting/updating R3 policy rather than an R2-only technical implementation. No registry or policy field was added, no trust root was regenerated, and no RA-01 status is upgraded. NT-01-1 through NT-01-5 remain GAP pending a CEO-approved, concrete normative route map (or an explicit R3 decision adopting an exact route map from §3.4.3).

## Remaining RA-02 implementation gaps

NT-02-1 and NT-02-2 now have a regression test for the existing control: `manifest_audit` takes implementer IDs from the anchored attribution source, while manifest producer and Git metadata only tighten recusal. The current R1 production check path does not verify check-run publisher App identity, and its attribution record does not bind a GitHub principal to a distinct authenticated actor. The legacy `pr_conformity.evaluate` boundary also has no authenticated actor input. These are not closed by tests against the trial harness or against supplied attribution fixtures; NT-02-3, NT-02-5, and NT-02-10 remain GAP. No production change was made for these because the repository contains no trusted actor-to-principal mapping or authorized check-App allowlist from which to implement the required bindings without inventing trust data. This is a limitation, not evidence that the controls exist.

## Evidence limits

- Unit tests use local repositories and existing fakes only; none establishes GitHub's live ruleset behavior or effective credential/protection configuration.
- The working tree’s policy itself labels RA-01 through RA-09 requirements as pending. This traceability document does not upgrade their state.
- No cases are marked PASS. An audited run must record exact source SHA, test command/output, relevant configuration, and independent auditor disposition before any acceptance claim.
